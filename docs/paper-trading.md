# 事件驱动模拟交易

模拟交易使用真实交易时钟推进，不再通过每天重跑历史回测重建账户。页面、数据库事件和执行日志必须表达同一件已经发生的事实；系统不得在收盘后把成交倒填成仿佛开盘时已经执行。

## 时钟链路

```text
15:30 数据管道完成 → 冻结 SignalIntent → 生成次日订单计划
09:25 盘前校验 → 09:30 开盘撮合 → 09:31 订单终态截止
盘中行情 → 持仓估值 / 盘中风险触发 → 15:05 结算与三账对账
```

盘后数据管道只计算最新完整数据日的一次策略上下文。模拟账户不会调用回测 worker；回测与模拟交易只共享确定性的费用、滑点、整手、T+1 和一字涨跌停规则。

## 账本与幂等性

账本位于运行时数据目录 `paper_trading/paper_ledger.sqlite3`，使用 SQLite WAL、外键、事务和唯一约束。账户、信号、订单、成交、持仓、资金流水、事件、异常和结算快照在一个账本内关联。

- 一个订单最多写入一笔成交记录；成交、现金和持仓在同一事务内更新。
- 信号、订单和事件使用稳定标识，调度重试不会重复生成。
- 每日结算重复执行不会重复增加持仓天数。
- 删除账户是运营界面的软删除；审计事件和历史账本保留。
- 服务重启后的开盘恢复先记录 `MISSED_EXECUTION`。09:30–09:31 分钟数据优先；交易日收盘后，也可使用该标的完整官方日 OHLCV，按与回测相同的 `open_t+1` 和全日一字板口径恢复。恢复成交标记 `RECOVERED_LATE`；两种证据都不足时进入 `UNKNOWN_MARKET_DATA`。
- `UNKNOWN_MARKET_DATA` 是 09:31 时点不可篡改的执行结果，不是永久死状态。订单仍留在证据恢复队列和行情订阅范围；本地分钟数据完成、盘后管道完成或单标的补拉取得证据后，账本追加 `RECOVERED_LATE` 成交或明确拒绝，并保留最初的未知事件。
- 证据恢复每分钟幂等检查一次，服务重启后从账本继续，不依赖某次进程的内存状态或部署时间。
- 当日 15:05 结算后才写入延迟成交时，系统原位重述同一交易日净值快照并追加 `SETTLEMENT_RESTATED` 事件；不生成重复日期、不重复增加持仓天数。

## 订单终态

开盘订单必须进入以下明确状态之一：

- `FILLED` / `PARTIALLY_FILLED`
- `REJECTED_LIMIT_UP` / `REJECTED_LIMIT_DOWN`
- `REJECTED_SUSPENDED`
- `REJECTED_INSUFFICIENT_CASH`
- `REJECTED_UNSUPPORTED_BOARD`
- `UNKNOWN_MARKET_DATA`
- `EXECUTION_FAILED`
- `MISSED_EXECUTION`
- `CANCELLED`

股票模拟账户固定只允许沪深主板。创业板、科创板和北交所会在候选冻结阶段排除；
如果历史配置或异常数据仍产生相关买单，09:25 盘前校验会以
`REJECTED_UNSUPPORTED_BOARD` 明确拒绝，不能进入开盘撮合。

`PLANNED` 和 `PREFLIGHT_OK` 是执行窗口内的中间态，不能在已确认的交易日 09:31 后被页面描述成成交。

## 退出模式

账户创建时必须选择退出模式：

- 盘后退出：完整日线封板后判断策略卖点、止损和止盈，生成下一交易日开盘卖单。
- 盘中风险：实时或分钟行情触发，生成下一有效行情卖单。

两种模式均执行 A 股 T+1。当日买入触发风险时，持仓只记录“已触发、T+1 锁定、等待可卖”，不会生成虚假卖出成交。

## 行情与失败降级

实时行情范围由用户自选股、所有模拟账户待执行标的和所有模拟账户持仓标的合并。持仓估值保留行情时间和来源。交易时段行情过期、错过开盘或三账不平会使执行器降级或报错，页面不能继续显示正常绿色状态。

模拟交易另有仅针对待执行与持仓标的的行情刷新，并附带一个上证指数开市探针；它不依赖页面的全局实时行情开关，也不会为了少量持仓每 10 秒重拉全市场。探针有效而订单标的缺失时，09:31 会明确进入 `UNKNOWN_MARKET_DATA` 并持续自动复核。恢复器先读取指定交易日的本地分钟数据，缺失时仅补拉相关订单标的；若全市场分钟分区因无关标的缺失而未发布，收盘后可独立读取订单标的的完整官方日 OHLCV，不重跑策略或整个回测。跨日才取得历史开盘证据时，补偿成交仍以原计划日开盘价记账，并按当前交易日正确解除已过去的 T+1 锁定。收盘后至 17:00 每 5 分钟复核持仓标的最终行情，服务在任意时间重启也立即补做一次；官方收盘价发生修订时，持仓估值与当日结算追加不可变重述事件，不会长期停留在临时快照。今日盈亏按当日事实计算：旧仓以昨收为基准、当日新仓以含费用成交成本为基准、当日卖出单独结转；持仓没有当日有效行情时页面显示未知，不用累计浮盈冒充今日盈亏。

交易日只有在当日有效市场行情被观察到后才确认；无法确认是否开市时订单保持计划态并产生 `TRADING_DAY_UNCONFIRMED`，系统不会把节假日猜成交易日。

## 旧账户迁移

启动时会幂等读取旧的 `paper_trading/accounts/*.json`：

- 保留原始 JSON 为审计快照；
- 迁移账户配置、初始资金和未执行信号/订单；
- 不导入旧回放产生的成交和持仓，避免把历史重放伪装成真实执行；
- 旧文件不会在迁移过程中删除。

## 发布与验收

所有变更必须先完成测试、提交并推送 GitHub，再由服务器执行 `git pull --ff-only` 后构建部署。最低验证包括：

- 重复执行不重复成交、扣款或持仓；
- 停牌、一字涨跌停、资金不足、行情缺失的固定终态；
- 09:29 重启后的 `MISSED_EXECUTION` / `RECOVERED_LATE` 证据链；
- 09:31 行情缺失后补齐、服务重启、跨日恢复都不丢单且不重复成交；
- T+1 锁定和下一交易日解锁；
- 每日资金账、持仓账和成交账一致；
- 页面状态、API 投影、数据库事件和执行日志一致。

# Serenity 卡点策略：最近一年事件回溯

## 目标与结论边界

本回溯检验一个可交易的短周期假设：已经具备卡点属性的公司，在出现新的、可核验的官方事件后，
是否能在下一交易日开盘成交，并在持有 2、3、5 或 10 个交易日后获得扣费正收益。

项目当前只有最近一年日线。程序从本地股票复权日线和沪深300共同覆盖区间自动取边界；截至本方案
冻结时，服务器实际区间为 2025-08-26～2026-08-27，共 244 个共同交易日。报告不得写成三年回测。

公告标题只用于发现候选 PDF，不是买入信号。没有完成 PDF 原文核验、64 分点时评分和成交检查的
记录固定为 `DISCOVERY_ONLY_REVIEW_REQUIRED`，整体结论固定为 `UNVERIFIED_ALPHA`。

## 冻结样本与偏差

- 沿用 7 天试验冻结的 100 家公司：半导体前道 34 家、AI 互连与液冷 33 家、锂电材料负对照 33 家；
- 不根据最近一年收益替换公司；
- 公司和概念成员来自当前快照，因此历史回溯存在存活偏差和成分漂移；
- 该偏差未解决前，即使收益为正也不能升级为可投入资金的 Alpha。

## 两层信号

### 慢变量：卡点先验

总分 100 分，严格使用事件决策日当时已经发布的材料：

| 维度 | 分值 | 信号门槛 |
| --- | ---: | --- |
| 需求拐点 | 15 | 财务公告从下一交易日起可见 |
| 估值错位 | 11 | 使用当时可见 BPS、ROE 和收盘价 |
| 催化时点 | 10 | 只使用决策日及以前的量价 |
| 架构耦合 | 10 | PDF 原文逐页引用，至少 6 分 |
| 卡点严重度 | 15 | PDF 原文逐页引用，至少 9 分 |
| 供应集中度 | 12 | PDF 原文逐页引用，至少 7.2 分 |
| 扩产难度 | 12 | PDF 原文逐页引用，至少 7.2 分 |
| 证据质量 | 15 | 至少 9 分，决定性引用必须可回查 |

八类风险仍按 0～5 级、每级 2 分扣减。只有五项 PDF 维度都能得到精确分、扣减后的总分不低于
70 分时，慢变量才通过。任何关键维度 `UNKNOWN` 都是 `DATA_INSUFFICIENT`，不能用上限分代替。

旧 7 天试验已经缓存的 98 份 DeepSeek 结果只能用于当前时点研究先验；若其中引用了事件日之后的
文件，不得用于该历史事件。历史评分必须重新构造“截至事件日”的 PDF 包和输入哈希。

### 快变量：新增事件

巨潮资讯公告按公司、按页完整查询。标题规则只发现以下候选：

- 中标、订单、重大合同或定点；
- 客户认证、验证通过、批量供货或正式量产；
- 涨价、停产、限产或供应短缺；
- 扩产、投产、开工、竣工或产能里程碑；
- 业绩预增、扭亏或明确上修。

减持、质押、立案、处罚、诉讼、项目或合同终止、业绩下修等是风险否决。同一公司同一决策日若
同时出现正向候选和风险公告，当日整组不产生多头事件。重复公告按公司和决策日合并为一个事件，
避免同一段收益被重复计算。

DeepSeek 只负责从原文判断事件是否真实、新增、重大且与卡点传导有关，并输出逐页原句。模型结果
必须先按 `event_id + input_hash` 原样落入 DuckDB，再做本地逐字引用校验；重试先读缓存，不重复付费。
新的最近一年批量语义分析必须另有明确人民币上限，旧 120 元授权不能自动沿用。

## 执行与收益口径

1. 公告无论盘中还是盘后发布，都在该交易日收盘后才允许形成决定；周末公告在下一个交易日收盘后决定；
2. 订单在决定后的下一个全市场交易日开盘进入，不使用事件日收盘价；
3. 停牌、无成交量或一字涨跌停视为不可成交，不假设买到；
4. 分别在持有第 2、3、5、10 个交易日收盘结算，单边进出合计固定扣 20 bp；
5. 同时记录沪深300超额、同产业链等权超额、MAE 和 MFE；
6. 公司日线使用本地复权 OHLC，指数使用本地指数日线；缺 K 线不插值、不结算；
7. 事件日接近样本尾部、尚未达到退出日的结果保持 `PENDING_OUTCOME`。

四个持有期先全部作为研究结果保存，不能事后挑收益最高者直接上线。若样本量足够，前约三分之二
交易日只用于选择一个持有期，后约三分之一作为锁定验证；样本不足则保持未验证。

## 数据与存储

- 研究库：`data/research/serenity_event/<replay-id>/pilot.duckdb`；
- PDF：同目录 `documents/`；抽取文本：同目录 `text/`；
- 行情只复制 100 家与沪深300最近一年所需行到研究库，不改写生产日线；
- 公告查询有逐公司完成状态，成功公司不会在重试时重复查询；
- 最多 600 份事件 PDF、每家公司最多 10 份、原始 PDF 总量最多 1 GB；
- 首次只下载 100 份，先看公告数量和官方文件体积估算，再决定是否继续；
- OCR 每份最多 8 个低文本页，临时页图不落盘。

## 验收门槛

工程层必须满足：

- 101 个价格目标（100 家公司加沪深300）的行数、起止日和无重复键均可审计；
- 公告查询逐公司有 `ok`、`empty` 或明确失败原因；
- 每份 PDF 有哈希、页数、字节、解析状态和逐页文本；
- 付费模型原始输出、输入哈希、模型名和成本记录不可变且可复用；
- 成交、复权、D+2/3/5/10 和风险否决有自动测试。

收益层最低显示样本数、均值、中位数、胜率、标准差、沪深300超额、同链超额和最差 MAE。任何
事件类型或持有期少于 20 个已结算事件，都标记 `INSUFFICIENT_OBSERVATION`。只有锁定验证区间至少
50 个可成交事件、扣费后的指数和同链平均超额均为正，且结果不是由单一事件或单一产业链驱动时，
才进入模拟盘候选；否则结论为无 Alpha 或证据不足。

## 分阶段运行

以下命令都在数据盘隔离目录执行。初始化默认读取股票与指数的共同本地日期窗口：

```bash
uv run python -m app.services.serenity_event_replay init \
  --root /app/data/research/serenity_event/serenity-event-1y-v1 \
  --source-root /app/data/research/serenity_pilot/serenity-historical-7td-20260826
```

先复制本地价格，再只抓公告元数据：

```bash
uv run python -m app.services.serenity_event_replay collect-prices \
  --root /app/data/research/serenity_event/serenity-event-1y-v1

uv run python -m app.services.serenity_event_replay collect-events \
  --root /app/data/research/serenity_event/serenity-event-1y-v1
```

查看报告中的候选数量和预计文件体积后，第一批最多下载 100 份：

```bash
uv run python -m app.services.serenity_event_replay download \
  --root /app/data/research/serenity_event/serenity-event-1y-v1 \
  --max-new-documents 100
```

只有完成语义核验后才结算正式事件信号。当前 `settle` 先输出明确标注的标题发现事件研究，不能当作
正式策略收益：

```bash
uv run python -m app.services.serenity_event_replay settle \
  --root /app/data/research/serenity_event/serenity-event-1y-v1
```
